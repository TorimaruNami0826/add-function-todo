### 06_AI生成コードの理解
- ゴール：全チェック項目を自分の言葉で説明できる状態
- 理解できていない箇所：
  - src/routes/todos.js の各エンドポイントが何をしているか説明できる
- 分解：
    TODOアプリの機能を定義している
    - GET /: データベースから全てのTODOデータを取得し、一覧として返す
    - POST /: 新しいTODOの内容を受け取り、データベースに保存する
    - PUT /:id: 指定したIDのTODOについて、完了チェックの状態などを更新する
    - DELETE /:id: 不要になったTODOをデータベースから削除する
- 理解できていない箇所：  
  - src/db/pool.js のコネクションプールがなぜ必要か説明できる
- 分解：
    データベースへの接続を毎回 作成・切断 すると
    サーバーに大きな負荷がかかり動作が遅くなるため
- 理解できていない箇所：  
  - public/index.html が API をどう呼んでいるか説明できる
- 分解：
    ブラウザ上の JavaScriptを使用して、裏側で API サーバーと通信する
    ユーザーがボタンを押したタイミング等で、指定したエンドポイントに対してリクエストを送り
    受け取った結果を画面に反映する
- 理解できていない箇所：  
  - .env がなぜ Git にコミットしてはいけないか説明できる
- 分解：
    .env ファイルには、機密情報が書き込まれている
    Gitに上げることで、誰でもその情報を閲覧できるようになり、不正アクセスや情報漏洩の原因となる
- 理解できていない箇所：  
  - マイグレーションファイルを自分で書ける
- 分解：
    テーブルの作成やカラムの追加手順をコード化しておくことで
    どの環境でも、同じ構造のデータベースを再現できる
- 理解できていない箇所：  
    jest.mock で DB をモックしている理由を説明できる
- 分解：
	①環境に依存させないようにするため
	②テストにおいて準備が大変なケースを容易に再現できるようにするため
	③ルーターのロジックのテストのみを実行するため
